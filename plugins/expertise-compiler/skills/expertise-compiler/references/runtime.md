# Runtime protocol

Read this reference when answering with an installed domain skill or evaluating whether a generated skill retrieves enough evidence.

## Follow the evidence path

1. Check vault status and identify the requested implementation, fork, and version.
2. Read `wiki/ROUTER.md` before opening broad content.
3. Decompose the task into concepts, exact symbols, constraints, versions, and required relationships.
4. Form several lexical and symbol hypotheses, including domain aliases and alternate-language terms.
5. Search for matching pages and symbols, then request a budgeted context pack.
6. Traverse hierarchical maps and graph links from broad systems to narrow components and source ranges.
7. Open the primary code or document spans behind every decision-critical claim.
8. Answer, plan, or patch only after the evidence is sufficient; otherwise state the precise gap.

Use narrow reads. Do not load an entire repository or document when the router, headings, symbols, and links can identify a smaller range.

## Interpret runtime artifacts

- Treat `ROUTER.md` as a route map, not evidence.
- Treat Wiki pages as explanations with provenance, not primary sources.
- Treat aliases and lexical scores as discovery aids, not proof of equivalence.
- Treat graph edges according to their confidence and deterministic origin.
- Treat a context pack as an evidence itinerary assembled under a token budget, not an answer.
- Treat raw source spans at the registered commit or snapshot as final evidence.

Resolve disagreement by version and source authority. Never silently combine implementations. Cite the applicable version and expose warnings when a result depends on an inference, approximate call edge, stale source, or incomplete coverage.

## Improve runtime safely

Use diagnostics to compare the expected evidence path with the actual trajectory. Repair routing, aliases, links, or page coverage rather than teaching the runtime to guess. Record successful work as a recipe only after external verification; never learn from an answer merely because it sounds plausible.

## Use the Codex harness

When a repository contains the managed Expertise Compiler block in `AGENTS.md`, obtain its evidence pack before repository decisions. Gather it directly or, if the current host supports delegation, use an available subagent. The active agent chooses every subagent type, configuration, and lifecycle detail; the harness does not prescribe any of them. No background service is installed.
